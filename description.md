# Buckshot Roulette - Desktop GameApp (Kotlin)

Десктопное приложение на Kotlin и Compose Multiplatform, разработанное для предоставления игрового процесса Buckshot Roulette с ведением локального словаря учетных записей, сохранением истории матчей и расчетом рейтингов игроков.

## Архитектура проекта
Проект следует паттерну **MVP (Model-View-Presenter)**:
* **View**: `MainUI.kt` отрисовывает все содержимое игры.
* **Presenter**: `GamePresenter.kt` хранит `UiState`, обрабатывает действия пользователя и синхронно вызывает методы Model.
* **Model**: `GameSession.kt` и сущности — движок, содержащий всю бизнес-логику. Методы возвращают результаты (`ShotResult`, `UseItemResult`, `RoundStartResult`) вместо генерации событий.
* **data Layer**: `StatisticsService.kt` сохраняет статистику по игроку, историю игр и таблицу лидеров.

## Расписание работы программы

### 1. Запуск программы
* **Точки входа**: При запуске `GameLauncher.kt` инициализируется графический интерфейс. Имеется также текстовый режим (`AppLauncher.kt`), организующий только бизнес-логику.
* **Инициализация хранилища**: При старте `StatisticsService` проверяет наличие локального файла `stats.db`. В случае его отсутствия Exposed ORM автоматически создает таблицы `players` и `match_history` для дальнейшей БД.

### 2. Подготовка игры
* **Конфигурация комнаты**: Администратор указывает целевое количество участников сессии (от 2 до 4 человек).
* **Авторизация и валидация**: Игроки поочередно вводят свои уникальные имена. Компонент `LoginScreen` проверяет их по списку `alreadyExist`, блокируя дубликаты. Параллельно `StatisticsService` выполняет SQL-запрос `SELECT`, подтягивая из базы историю побед и винрейт ветеранов, либо создает запись для новой учетной записи.
* **Сборка контекста**: На основе введенных имен создаются объекты `Player`. Инициализируются `Presenter` и `GameSession`. Presenter вызывает `startGame()` для запуска первого раунда.

### 3. Игровой цикл
* **Генерация раунда**: Вызов `startRound()` случайным образом рассчитывает количество боевых и холостых патронов. Магазин перемешивается методом `barrel.shuffle()`. Инвентарь каждого живого участника заполняется случайными предметами (`Item`). Метод возвращает `RoundStartResult` с количеством патронов и именем первого игрока.
* **Передача хода**: В функции `shot()` вызывается `nextTurn`, который определяет, кто будет следующим. Результат возвращается как `ShotResult.TurnEnded`.
* **Взаимодействие со стейт-машиной**: Активный игрок применяет по желанию инвентарь и обязательно совершает выстрел. На основе типа патрона (`AmmoType`) рассчитывается полученный урон. Предметы возвращают `ItemEffectResult`, который Presenter преобразует в логи или информационные сообщения.

### 4. Вывод
* **Рендеринг состояния**: Экран `TableScreen` считывает изменения `UiState`.
* **Информационные панели**: UI выводит результаты применения предметов из `uiState.logs` и `uiState.infoMessage`.

### 5. Логирование и выход
* **Синхронное обновление**: Каждое действие пользователя синхронно вызывает метод Model, получает результат и обновляет `UiState`, что триггерит рекомпозицию UI.
* **Фиксация итогов**: При срабатывании статуса `GAME_OVER` Presenter получает `ShotResult.GameOver` или `UseItemResult.GameOver`, обновляет `uiState.isGameOver = true`. Выживший победитель определяется через `session.getWinner()`, после чего отправляется атомарная транзакция в БД через `updateStats`. Записывается UUID матча, обновляются счетчики игр и побед. После можно вернуться в главное меню или просмотреть глобальную таблицу `LeaderboardScreen` или историю матчей `MatchesHistory`.

## Тестирование
В проекте реализована многоуровневая пирамида тестирования на базе (`gradle test`):
* **Unit-тесты**: Изолированная проверка логики ружья (`ShotgunTest`), лимитов игрока (`PlayerTest`) и эффектов всех предметов (`GameItemsTest`).
* **Регрессионные тесты**: Проверка корректности обновления статистики и формирования таблицы лидеров (`DatabaseSpecificationTest`).
* **Интеграционные и Системные тесты**: Проверка раздачи предметов, смены хода, заряженность дробовика до его использования и E2E симуляция дуэли.
